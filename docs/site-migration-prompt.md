# Универсальный промпт: перенос сайта через Cursor

Скопируйте в новый чат в режиме **Plan**. Подставьте значения в `[...]`.

**Пароли в первый промпт не вставляйте.**  
Порядок: 1) бриф без доступов → 2) план и ответы на вопросы → 3) отдельным сообщением доступы к тесту → 4) «начинай».

Шаблон сообщения с доступами и правила безопасности — в `docs/site-migration-instruction.html`, раздел «Когда и как передавать доступы».

```text
Давай составим полный план действий. Если что-то непонятно — задай вопросы, не додумывай.

Ты — веб-разработчик. Задача: перенести сайт с [ИСТОЧНИК: Tilda / другой конструктор / CMS / самопис] на [ЦЕЛЬ: WordPress / WordPress+WooCommerce / Bitrix / HTML].

Эталон (основной сайт): [URL_ЭТАЛОНА]
Куда переносим (тест): [URL_ТЕСТА]

Цель результата:
- тестовый сайт выглядит и ведёт себя 1 в 1 как эталон: контент, вид, функционал, эффекты, адаптив;
- переносим [весь сайт / список страниц: …];
- код источника НЕ копируем и не переносим «мусор» конструктора/старой темы;
- каждый блок верстаем заново, но визуально и по поведению — 1 в 1.

Требования к коду:
- чистый, читаемый, поддерживаемый код;
- методология БЭМ (если в проекте уже другая строгая схема имён — следуй ей и скажи об этом);
- семантическая вёрстка, HTML5/CSS3;
- адаптив и кроссбраузерность для современных браузеров;
- базовая доступность;
- SEO-аккуратная разметка;
- ничего не выдумывать: только реальный эталон и реальные файлы целевого проекта.

Ассеты:
- не подключать стили/скрипты/изображения с хоста или CDN источника;
- всё нужное скачать и разместить локально в новом проекте, затем подключить оттуда.

Шрифты:
- только свободные шрифты (предпочтительно Google Fonts);
- если на эталоне шрифт есть в Google Fonts — использовать его;
- если точного нет — ближайший свободный аналог (согласовать).

Сквозные блоки и шаблоны:
- повторяющиеся блоки выносить в отдельные файлы и подключать в шаблонах;
- для страниц с одинаковой структурой — шаблоны;
- главную реализовать в шаблоне;
- простые статичные страницы — через стандартные страницы CMS и контент в админке, где это возможно.

[Если WordPress:]
- тема должна содержать стандартный набор файлов и функций темы, чтобы плагины работали нормально;
- меню — через стандартные меню WordPress, стилизация всех уровней 1 в 1 с эталоном;
- при наличии Classic Editor и ACF — использовать их по назначению.

[Если WooCommerce:]
- стилизовать шаблоны магазина через overrides в папке woocommerce темы;
- массово товары/категории [не переносим / переносим];
- для теста создать [N] демо-товаров/категорий;
- страница каталога: [URL].

[Если Bitrix / другая CMS / HTML:]
- править только реальные шаблоны/компоненты проекта;
- ядро CMS не трогать;
- повторить принятую в проекте схему шаблонов.

Формы:
- [A: заглушки + список страниц с формами]
- [B: модуль … + стилизация под эталон]
- [C: иное]

Прочее:
- cookie-баннер: [нужен / не нужен]
- аналитика (Метрика/GA): [переносим / не переносим]
- микроразметка schema.org: [нужна / не нужна]
- комментарии в сложных местах шаблонов — на русском, коротко

Порядок работы:
1) полный план и вопросы;
2) доступы к тесту — отдельным сообщением после согласования плана;
3) аудит эталона;
4) каркас темы/шаблонов;
5) шапка, меню, футер;
6) главная до 1 в 1 (несколько итераций);
7) остальные страницы/шаблоны;
8) формы, аналитика и допы;
9) финальный проход по всем URL.

Оцени задачу и скажи, сможешь ли реализовать. Пока я не скажу «начинай» — код не пиши, только план и вопросы.
Доступы к тестовому сайту пришлю отдельным сообщением после согласования плана.
```
