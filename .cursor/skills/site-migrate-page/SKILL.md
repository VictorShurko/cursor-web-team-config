# Перенос сайта / страницы

## Суть

Вид и поведение — 1 в 1 с эталоном. Код источника не копируем: блоки верстаем заново (БЭМ, семантика, поддерживаемый код). Ассеты — только локально в новом проекте.

## Перед работой

1. Уточни: URL эталона, URL теста, источник, целевая CMS, объём (весь сайт / список URL).
2. Уточни: формы, меню, аналитика, cookie, шрифты, Woo/товары, ACF.
3. Не выдумывай структуру темы/компонентов — сначала изучи целевой проект и эталон.
4. Пока пользователь не сказал «начинай» после плана — только план и вопросы.
5. Доступы к тесту — только после согласования плана, отдельным сообщением. Не просить пароли в первый бриф. Не сохранять пароли в файлы проекта и git.

## Порядок

1. План и вопросы (без паролей)
2. Доступы к тестовому сайту отдельным сообщением → затем реализация
3. Аудит эталона (страницы, блоки, шрифты, сквозные части)
3. Каркас темы/шаблонов целевой CMS (полный стандартный набор, если WP)
4. Шапка, меню (через CMS), футер
5. Главная до 1 в 1 — несколько итераций сравнения
6. Остальные шаблоны/страницы; одинаковые блоки — в отдельные файлы
7. Формы / магазин / аналитика — по брифу
8. Финальный проход по всем URL; убрать лишнее, чего нет на эталоне

## Запрещено

- Копировать HTML/CSS/JS конструктора «как есть»
- Hotlink на CDN/хост источника
- Выдуманные файлы, поля, шаблоны
- «Made on Tilda» и аналоги
- Типичный CMS-мусор (крошки, лишние page-header), которого нет на эталоне
- Ломать уже принятые шапку/футер/главную при работе над внутренними страницами

## Результат этапа

- Что сделано
- Какие URL/блоки сверены
- Что ещё отличается
- Список форм/страниц на доработку человеком (если так решили)
